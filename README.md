# AI 私人厨师 · Windows 便携版

**普通使用者：[点击下载 Windows 完整便携包](https://github.com/fym20060708-del/AI-Personal-Chef/releases/latest)。请下载发布附件中的 ZIP，GitHub 的 Download ZIP 仅含源码，不包含运行环境。**

上传食材照片或输入食材清单，获取按营养价值和制作难度排序的菜谱建议。支持流式回复、查看历史记录和清空对话。

## 在 Windows 上打开

1. 将整个压缩包解压到你有写入权限的文件夹，例如桌面。**不要直接在压缩包里双击运行。**
2. 用记事本打开 `.env.example`，填写下面的配置，再另存为同一目录下的 `.env`。记事本的“保存类型”选“所有文件”，避免保存成 `.env.txt`。也可以先双击启动脚本，让它自动生成 `.env` 后再编辑。
3. 双击 **`启动网页.cmd`**。无需安装 Python，也不需要运行 npm。
4. 等待默认浏览器打开 **http://localhost:8001/**。未自动打开时，用 Edge 或 Chrome 手动输入该地址。
5. 点击上传按钮，选择食材照片，并输入要求，例如“推荐三道营养均衡、半小时内能做好的菜”。也可以直接输入食材清单。
6. 使用期间保留启动窗口；按 **Ctrl+C** 或关闭窗口停止服务。

适用于 **Windows 10/11 64 位**。网页与服务在自己的电脑上运行；图片识别、食谱搜索和图片上传仍需联网，并可能产生第三方服务费用。其他电脑需各自解压和配置后使用。

## 首次配置

每位使用者使用自己的账号和密钥，不要把 `.env`、带密钥的截图或聊天数据库发给别人。

| `.env` 配置项 | 填写内容 |
| --- | --- |
| `DASHSCOPE_BASE_URL` | 百炼 OpenAI 兼容接口地址，模板是北京区域地址；应与账号、密钥和模型区域匹配 |
| `DASHSCOPE_API_KEY` | 自己的百炼 API Key |
| `DASHSCOPE_MODEL` | 账号中已开通、支持图片输入的模型名称；按服务控制台填写，不要随意填写纯文本模型 |
| `TAVILY_API_KEY` | 自己的 Tavily 搜索 API Key |
| `OSS_ACCESS_KEY_ID` | 有目标存储桶所需权限的阿里云 AccessKey ID |
| `OSS_ACCESS_KEY_SECRET` | 对应的 AccessKey Secret |
| `OSS_BUCKET` | OSS 存储桶名称，不带 `https://` |
| `OSS_ENDPOINT` | OSS 域名，不带协议和桶名前缀，例如 `oss-cn-beijing.aliyuncs.com` |
| `OSS_REGION` | 存储桶所在区域，例如 `cn-beijing` |

配置文件每行使用 `名称=值`，修改后重启程序。不要把真实密钥写进 `.env.example`。

### OSS 图片上传设置

当前程序先通过浏览器把图片上传到 OSS，再把图片 URL 发给模型识别，因此需要：

- 为使用的凭证授予目标桶的图片上传权限；配置与桶所在区域保持一致。
- 在桶的跨域规则中允许来源 `http://localhost:8001`（如使用 `127.0.0.1`，也添加 `http://127.0.0.1:8001`），允许 `PUT`，允许 `Content-Type` 请求头。浏览器的预检请求必须能通过。
- 当前代码返回的是未签名的图片读取 URL。上传对象需要允许模型从公网读取；请用专门存放可公开食材照片的桶，避免上传含个人信息的照片。私有桶读取需要另行实现带签名的读取 URL。

如不配置图片上传，可先完成必要配置后通过输入食材清单验证聊天；当前启动器仍会检查整套配置是否齐全。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 提示配置尚未完成 | 编辑启动脚本旁的 `.env`，补齐提示中的配置项，再启动；检查是否误存成 `.env.txt` |
| 提示端口 8001 被占用 | 关闭占用该端口的程序后重试；如果本项目已经运行，启动器会直接打开已有网页 |
| 页面无法访问 | 查看启动窗口是否报错、是否被关闭；确认输入的是 `http://localhost:8001/` |
| 图片上传失败 | 检查 OSS 凭证权限、桶名称、区域、跨域设置及网络；查看浏览器报错 |
| 上传成功但无法识别 | 检查模型是否支持图片、图片 URL 是否可从公网读取，以及账号额度 |
| 信息检索失败 | 检查百炼、Tavily 配置及额度，查看启动窗口日志 |
| 找不到 runtime 中的 python.exe | 重新完整解压发布包，不要只复制启动脚本；源码目录不含便携运行环境 |
| Windows 提示文件来自互联网 | 只运行来源可信、由你确认的发布包；不要为启动软件关闭系统安全保护 |

聊天记录保存在 `data/personal_chief.db`。停止服务后删除 `data` 中数据库文件会清空本机历史；应用不会自动导入旧项目数据库。日志显示在启动窗口中，提交问题前请遮住凭证与个人信息。

## 开发与重新打包

下面内容仅供维护者使用，普通使用者不需要执行。源码中的 `app` 是 Python 包，开发环境依赖见 `requirements-runtime.txt`。

在克隆后的仓库根目录，使用已安装运行依赖和 `packaging` 的 Windows 64 位 Python 执行：

```powershell
python scripts\launch.py
python scripts\build_portable.py
```

源码采用 `app/`、`scripts/` 和根目录配置文件的结构。源码启动器读取仓库根目录的 `.env`；请复制 `.env.example` 后填写自己的配置，**不要提交真实配置**。首次准备开发环境可运行 `python -m pip install -r requirements-runtime.txt`。

构建脚本从当前解释器复制标准库、DLL 及运行依赖的传递依赖，无需联网下载；不会复制整个开发虚拟环境，也不会复制 `.env` 或旧数据库。输出目录为 `dist/AI-私人厨师-Windows`，旁边生成同名 `.zip`。若输出目录已存在，先移走旧产物再构建，防止覆盖已有配置和数据。依赖许可证保留在运行环境的包元数据中，Python 许可证在 `runtime/LICENSE.txt`。

发布前请在无 Python 的 Windows 电脑上验证启动，并用有效服务配置验证图片上传、推荐、历史记录和清空对话。
